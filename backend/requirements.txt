# 这里刻意使用「精确版本」而不是 >= 范围，原因是一次真实的构建事故：
#
# 原来写的是 fastapi>=0.110，没有上界。pip 会从最新版开始向下逐个试，
# 因为 fastapi 每个版本对 pydantic 的约束都不同，解析器会一路回溯到
# 0.110.0（约 60 个版本）。这会向镜像站发出**几百次**元数据请求，耗时
# 7 分钟以上；期间 pydantic 的索引页一旦被限流/超时，pip 就会认为
# 「pydantic 一个可用版本都没有」，于是所有 fastapi 版本全被判为冲突，
# 最终报 ResolutionImpossible —— 报错内容指向 pydantic，但根因是无上界。
#
# 锁版本后：pip 只需十几次请求，秒级完成，且构建结果可复现。
# 升级依赖时请连同下面这几个一起改，并重新构建验证（见 README）。
#
# 版本组合已在 Linux x86_64 / Python 3.12 / pip 25 与 26 上验证可解析。
# ─────────────────────────────────────────────────────────────────────────────
